# Online evaluation architecture

Cloudflare Workers Static Assets serves the existing React 19/Vite 7 application and prerendered public pages. A small Fetch gateway forwards only /api and /v1 to one persistent Node 22/Express 5 instance on Render. User JWTs and exact Origin headers are preserved. The backend keeps the existing pg pool, checked-out-client transactions/AsyncLocalStorage, legacy APIs, tenant authorization, JOSE and domain services. There is no framework conversion, direct browser SQL, Hyperdrive or competing database layer.

An unchanged Worker deployment is unsuitable for the complete existing backend: src/db/adapter.ts statically imports native better-sqlite3; index.ts owns 10/15-second polling and process lifecycle; Orbit has in-process queues; internal documentation routes read packaged files. Workers Node compatibility does not supply persistent process lifetime or durable in-memory queues. A future edge port requires reviewed adapter, scheduled consumer, outbox-claim and deployment work, rather than pretending nodejs_compat is a complete port. See https://developers.cloudflare.com/workers/platform/limits/.

No Python service exists. Statement imports are JSON/text. Evidence payloads/keys are encrypted in PostgreSQL; PDFs use browser printing, illustrations/fonts are public build assets. No laptop upload directory or new R2 bucket is required. Retain single-instance execution: distributed leases and shared rate limits are not implemented.

The evaluation reuses the explicitly approved development branch containing existing identities: br-jolly-lake-b4ff04st in autumn-water-21744826. NODE_ENV=production hardens HTTP/runtime behavior while AFRICORE_ENVIRONMENT=development preserves the existing database environment. This is not a new production financial deployment, a copied identity namespace, or a claim of production readiness. Do not run a competing local job processor against the same branch during online evaluation. Production remains untouched.

Hosted startup uses AFRICORE_MIGRATIONS_MODE=verify: require all five recorded schema versions and core tables using SELECT only. Apply reviewed migrations separately before changing this mode. This avoids repeating legacy ALTER/RLS DDL and locking existing data during each hosting restart. Local default remains migrate.
