# Protected payments: sandbox orchestration
Implementation: src/stage2/commerce.ts. Production creation, buyer activity and settlement return unavailable. The deterministic partner adapter is a simulator. AfriCore holds no real funds and implements no wallet, escrow account, refund rail or license. Provider confirmation states in sandbox mean simulator confirmation only.

Create an agreement with title, amount/currency, delivery/cancellation terms, inspection hours and merchant support. An optional unpaid uninvoiced order must match the amount; otherwise a canonical sandbox order/recipient is created. Existing standard links are cancelled and further standard checkout/invoicing/order mutation is blocked while the agreement is active. The returned buyer URL is shown once: opaque token, hashed at rest, expiry 1–30 days (14 default), revocable on seller cancellation/expiry. Store it securely; there is no token recovery endpoint.

Journey: awaiting_buyer_payment -> payment_pending -> payment_confirmed_by_provider -> protected_arrangement_confirmed -> awaiting_shipment -> shipped -> delivered -> inspection_period -> accepted -> release_requested -> released_by_partner. Payment, arrangement, custody, fulfillment and settlement fields remain distinct. Buyer pay invokes the server simulator, never a browser success assertion. Full receipt requires every purchased quantity to have shipped; buyer confirmation carries customer-confirmed assurance. Acceptance does not transfer money.

A human requester obtains a different owner/admin approval, then requests release. A separate explicit simulator settlement call records its result. Open disputes block settlement. Commands and create calls require stable Idempotency-Key; conflicting reuse fails, repeated commands return the prior result. Events/audit/history persist. Simulated settlements do not manufacture real-money journal entries or bank balances.

Unpaid agreements may cancel/expire; paid outcomes use dispute review. No automatic inspection-time release, partial protected settlement, real partner callbacks or unconditional protection guarantee is implemented. Buyer links are bearer capabilities, not verified legal identities. Production requires all gates in COMPLIANCE_GAPS_STAGE2.md, authenticated signed partner evidence, settlement reconciliation, operational support and security review.
