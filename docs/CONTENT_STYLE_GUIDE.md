# Content style guide

Use concrete business tasks before technical terms. Explain what a tool does, who uses it, the input, the next action and the result. Write short active sentences. Define reconciliation, receivables, credentials and anchors before relying on those words.

Distinguish requested money, confirmed receipts, outstanding invoices and recorded expenses. Net movement is not profit or an available bank balance. Every monetary example names a currency. Fictional stories and local simulations must be labelled beside the example, not only in the footer.

Describe sandbox functionality precisely. Never promise lending, settlement, government approval, universal issuer recognition or truth from a signature/anchor alone. State an unavailable integration at the point where readers would otherwise expect it.

Each product guide needs a specific audience, problem, workflow, example, benefit, limits, FAQs and useful next step. Avoid repeating generic trust/security copy as the explanation. Keep illustrations supplementary: important numbers, instructions and labels belong in semantic HTML. Use descriptive links, contextual image alternatives and keyboard-operable controls.
