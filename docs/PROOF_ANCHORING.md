# Proof anchoring
Owner: AfriCore engineering/operations. Reviewed 2026-10-26.

Version africore-merkle-v1. domain=keccak256(UTF8('AfriCoreVCCommitment:v1')). For the exact signed compact credential token, digest=SHA256(UTF8(token)); salt is random32bytes. commitment=keccak256(abi.encode(bytes32 domain,bytes32 digest,bytes32 salt)). OpenZeppelin StandardMerkleTree uses values [domain,commitment] and types [bytes32,bytes32], with its standard double-hashed leaves and sorted pair hashing. This defines a documented commitment protocol, not a new hash/signature algorithm or arbitrary JSON canonicalizer.

Salts/individual proofs are encrypted off-chain and disclosed only with authorized holder exports. A batch contains up to100 unbatched active sandbox credentials. Unique credential/batch/root constraints prevent duplicate batching. Root-only publish queue stores transaction hash, state, attempts, next retry, confirmation/block metadata and measured gas/wei cost. No per-SME gas payment or wallet is required.

The single-instance worker polls15seconds. States include queued, submitted, retrying, confirmed, reorged and failed. It checks configured chain ID/address/code existence, queries existing roots before sending, persists submitted hash, reconciles receipts and waits for configured confirmations (local1, Sepolia default3). Retries use bounded exponential backoff, five attempts then failed; an operator may retry after repair. RPC failures are safely coded rather than persisting credential-bearing URLs. Rechecking a confirmed root can detect disappearance/reorg and prevents relying solely on a database flag. Full adversarial reorg/nonce-provider fault injection remains further qualification work.

Independent verification recomputes commitment and inclusion, queries the explicitly pinned chain/contract, reads the root's block and applies confirmation policy. Receipt/block metadata is checked by the service; exports identify last check. Missing RPC, wrong chain/contract, tampered salt/token/proof, unavailable root and insufficient confirmations remain distinct outcomes. RPC honesty/availability and contract/admin identity remain trust assumptions. Pin trusted deployment metadata and use independent RPCs for high assurance. No public testnet transaction or fiat-cost estimate is invented.

Local workflow: npm run chain:node; npm run chain:deploy; configure AFRICORE_ANCHOR_RPC, ADDRESS, CHAIN_ID and CONFIRMATIONS; authorize operator batch creation/process. Export a holder credential bundle, then npm run verify:credential -- --file bundle.json --rpc URL --contract ADDRESS. The connected demo supports AFRICORE_DEMO_CHAIN=true after local deployment. Local chain resets require redeployment/configuration and reconciliation; cached confirmations are not sufficient.
