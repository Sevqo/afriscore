# Stage 3 security review
Owner: AfriCore engineering/security. Reviewed 2026-10-26. Internal implementation review only; no independent security audit is claimed.

Threats considered: tenant/environment substitution, forged issuer/admin roles, signed self-attestations presented as source proof, malicious remote key URLs, malformed JOSE/profile/status entries, stale/revoked/compromised keys, expired/future credentials, consent/request substitution, bearer-link leakage, one-time replay, insider database edits, collusive counterparties, forged files, duplicate commitment publication, incorrect RPC chain/address, unavailable networks and reorgs.

Implemented: existing session/scoped-key authorization; admin-only trust mutations; separate verified operator approval; holder evidence authorization/withdrawal/expiry; source/category/hash checks; strict JOSE alg/typ and minimal schema; no arbitrary issuer fetch; encrypted custody; permanent revocation and retired/compromised distinction; fresh signed bitstring lists; recipient/audience/nonce/purpose/type binding; atomic one-time access; safe download types/limits/hashes; source correction propagation; Passport material-change review reset; randomized roots and OpenZeppelin proofs; immutable access-controlled no-funds contract; bounded public verification and retry queues.

Tests cover genuine signatures and tampering, independently implemented Node verification, encryption at rest, unknown issuer handling, wrong issuer binding, malformed/expired credentials, status/rotation/compromise, source/authorization change, tenant denial, recipient restriction, purpose/nonce/audience/replay/expiry/revocation, private documents/manual review, genuine local root inclusion and contract access/duplicate/pause/no-fund controls. Exact final counts and unexecuted checks are in STAGE3_TEST_RESULTS.md.

Known assumptions: backend DB owner bypasses RLS and remains trusted; encryption master key protects custody, but DB/key/host compromise can alter service records; local EVM operator controls/resettable chain; publishers/registry governance and RPC honesty still matter; browser demo storage is public synthetic state; counterparty accounts may collude; snapshots can be stale within their validity interval; authorized recipients can retain copies.

Remaining gates: KMS/HSM and dual control, independent issuer identity/domain checks, external OpenID conformance, broad cross-implementation VC suites, malware scanning, physical purge/holds/rights handling, fully independent appeals, distributed worker leases/shared limits, comprehensive property/fuzz/reorg/nonce/load tests, observability alerts, full accessibility audit, external contract/backend assessment and privacy/legal signoff. Production signing/anchoring remains disabled until these are resolved.
