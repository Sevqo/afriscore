# Key management and recovery
Owner: AfriCore security/trust operations. Reviewed 2026-10-26.

Sandbox issuer and managed-holder keys are separate ES256 key pairs generated by jose. Each has a unique kid, owner/environment, public JWK, state and encrypted private JWK. Private material never appears in API metadata, source control, frontend bundles or browser storage. Existing platform authenticated encryption seals private keys, credentials, grants, identity records and evidence. Protect AFRICORE_ENCRYPTION_KEY separately from databases/backups; production startup already requires encryption configuration.

States: active signs; retired remains valid for historical verification; compromised is rejected. Routine issuer rotation retires old active keys and creates a new key. Compromise deactivates the active key and revokes dependent credentials; historical roots remain. Record an incident reason/audit event. Status lists are signed by the current active key. Fresh public metadata is needed to learn compromise; old offline copies may be stale.

Recovery: restrict access, suspend issuer if needed, preserve evidence/logs, rotate encryption/signing secrets through an operator-controlled procedure, restore-test encrypted custody and reissue corrected credentials with fresh holder authorization. Never overwrite a signed credential or ask an SME to recover a seed phrase. Lost encryption keys can make stored credentials/private keys unrecoverable; there is no magic key recovery. Managed-holder key recovery/rotation self-service remains a production gate.

Production issuance is disabled. KMS/HSM signing, independent recovery controls, access attestations, dual-control ceremonies, rotation of encryption wrappers and audited issuer onboarding are not implemented. Disposable local keys must never be reused in production. Publisher signing is independent: local node's unlocked test account; optional Sepolia disposable key only when explicitly configured and gated. Mainnet keys are not accepted.
